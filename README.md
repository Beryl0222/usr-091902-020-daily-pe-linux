# 学校体育实课运行

核对"每天一节体育课"是否真实发生：带版本的学期方案、教师/场地/抽样学生的最小化交叉确认、
有依据的调课与极端天气替代、伤病适配、教会·勤练·常赛的可解释覆盖，以及对未成年人数据的分级可见。

## 运行

```bash
python3 service.py --check     # 基础配置检查
python3 service.py --port 8000 # 启动 HTTP 服务
npm test                       # 运行全部单元与接口契约测试
```

## 领域规则（均有测试覆盖）

**学期方案带版本**（学校管理员提交，`POST /api/plans`）

* 每个教学班每周一至周五每天一节体育课，活动覆盖体育课、大课间、课后服务、班级赛事；
* 每条安排对应场地（室内/室外、安全容量）、教师（教师资格与技能点资质）、技能目标；
* 同场地/同教师/同班时段冲突、容量不足、资质不符一律校验失败；
* 重新提交自动形成新版本并作废旧版本，课表变更可追溯，便于识别"阴阳课表"。

**实际授课：最小化事件交叉确认**（`POST /api/events`）

* 三类来源：教师签到、场地状态（可用/不可用）、抽样学生（每节 3~8 人，按活动轮换）；
* 三类齐备且有开始/结束才计"已完成"，否则为"部分完成"并进入复核线索；
* 重复教师签到、重复抽样、设备 `client_ref` 重复提交均被拒绝；运动时长只取首段开始-结束并裁剪到计划时长，重复签到不能虚增；
* 离线补签允许课后 7 日内提交，须被其余两类来源印证后才计时，印证前保持"待核对"。

**调整必须有依据**

* 临时占课/调课：须附通知编号、来源、事由（`/api/occupy`、`/api/reschedule`），占课不销账，原课转"待补课"；
* 降雨/高温替代：须引用当日本校天气记录（雨、或 ≥37℃），替代场地必须为室内且仍挂技能目标（`/api/weather-substitution`）；
* 伤病适配：须附医务/家校依据、适配强度（降低强度/见习观摩/免修休养）与起止日期（`/api/adaptations`），免修学生不入抽样；
* 补课（`/api/makeups`）归属原周次，完成后自动销缺口。

**覆盖：教会、勤练、常赛（可解释，不用单一体测分数）**

* 教会：每个计划技能点至少教授 2 次且有合格及以上技能等级观察；
* 勤练：周体育时长 ≥200 分钟、大课间实际比例 ≥80%，八成周达标；
* 常赛：每 9 个已历经周至少完成一场班级赛事；
* 每条结论同时返回规则文字与证据（授课场次、周时长、赛事记录）。教师只能记录技能等级（优秀/良好/合格/待提高），系统不接收分数与影像。

**异常先复核，不自动处罚**

* 自动识别：阴阳课表（实课被占、有课无记录）、替代未落实、极端天气缺替代、整节自由活动（≥3 节）、
  只练考试项目倾向、交叉确认不足、离线补签待核对、三支柱覆盖不足；
* 异常只进入教研复核清单（`/api/anomaly-roster`），由教研员裁定 已确认/已排除/已整改（`/api/reviews/resolve`）。

**连续意外后的还原**：`GET /api/reconstruct?class_id=…` 串起
方案版本 → 调整依据 → 逐节事件 → 每日状态/时长 → 缺口 → 补课安排 → 复核结论，
场地冲突、临时占课与离线补签连续发生后仍能还原每班真正完成的内容。

## 隐私分级

* `GET /api/public/school-summary`：公众只见学校级聚合（课时完成率、班均周时长、达标班级数、待复核项数），无任何师生明细；
* `GET /api/parent?token=…`：家长令牌由学校管理员签发（`POST /api/parent-token`），只能查看自己孩子的伤病适配、技能观察与被抽中日出勤，看不到他人数据；
* 班级明细、事件链、异常清单仅教研员/学校管理员可查。

### 身份传递

写接口在 JSON 体内携带 `actor`（`role` 取值：体育教师/教研员/学生家长/学校管理员）；读接口通过请求头
`X-Actor-Role: researcher|admin|teacher|parent`（HTTP 头不支持中文，故用代号），可选 `X-Actor-Id`。
错误响应统一为 `{"error": ..., "message": ...}`，状态码：403 角色不足、404 资源不存在、409 冲突/重复、422 校验失败。
